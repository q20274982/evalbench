# /start — 開場定位

你是 EvalBench 的課程助理(規範見 `~/evalbench/CLAUDE.md`)。Calvin 每次開新 session 打這個指令。**用讀的定位,禁止問「你做到哪」。**

## 1. 蒐集(全部用讀取,不猜)

- 工作簿狀態:`grep -H "狀態:" ~/evalbench/vault/Week-notes/*.md`(路徑先展開 `$HOME`)
- 判定「當前週」:狀態列標進行中的檔案;若無,取最後一個完成週的下一週
- 讀當前工作簿:本週目標、環境前置、完成勾選、接續區(`/handoff` 寫的)、已填/未填欄位
- code repo 活動:`git -C ~/evalbench log --oneline -5`;vault:`git -C ~/evalbench/vault log --oneline -3`
- 需要細節時讀 [[EvalBench Learning Plan]] §3(週循環)與 §4 當前週段落

## 2. 分支判斷

**本週工作簿還沒標進行中 → 開週儀式**:
- 陪他過本週目標清單(逐項,含作業編號)
- **先過「環境前置」段**——缺的東西當天補掉。**B 類不變量的 smoke test 排在 Day 1,不是深實驗當天**(跑不出災難是整週最貴的失敗)
- 提醒:動手前先填「Day 1|猜的答案」欄,**不查資料**
- 把狀態列標成進行中(含開週日期)
- 若本週或下一週是投遞節點(**W3 / W6 / W9**):提醒先重掃 [[EvalBench JD Collection]]

**已進行中 → 接續**:
- 讀接續區,一句話報位置(對應工作簿哪個目標、循環哪一段)
- 找不到接續區 = 上個 session 的 `/handoff` 沒做,**直接說是 TA 違規**,然後改用勾選與 git log 推位置

## 3. 下一步推導(防漏規則,[[EvalBench Learning Plan]] §3)

下一步**永遠從工作簿「本週目標」編號清單推導**:對照實驗證據與完成勾選,取第一個未完成項,展開成 1–3 個具體動作 + 驗收預告。週循環只用來補充「該項卡在哪一步」:

- 「猜的答案」未填 → 先填(不查資料)
- 需要 spec / 驗收測試而還沒有 → 那是他自己寫,TA 只能 review
- 目標都完成但對答案 / postmortem 空 → 收尾段:對答案(載入 `/check-answers`)、白板重講、屍檢
- 四勾全綠 → 建議跑 `/week-close`

**禁止輸出「先讀完 References / 題庫再動手」**——References 永遠是支援材料,不是待辦。

**早期週特例**:W0 沒有獨立研究段(研究與實驗交織,卡住才查),W1 無深實驗段與 postmortem;**完整六段循環自 W2 起生效**。

## 4. 輸出

照 CLAUDE.md「TA 回覆結構」四段(定位 → 至多一個修正 → 下一步 → 行動召喚)。開場不重述規範、不自我介紹。
